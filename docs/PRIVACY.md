# PRIVACY — プライバシーの扱い

原則として個人情報を収集しない。アプリ内の表示（設定 → プライバシーについて）と同じ内容。

## 収集・保存・送信しないもの

- 氏名 / 住所 / 電話番号 / メールアドレス（入力欄そのものがない）
- ユーザーアカウント
- GPS現在地の緯度経度
- カード取得履歴のサーバー送信
- チェックイン結果のサーバー送信
- SHIKA COIN 残高のサーバー送信
- 「気になる」情報のサーバー送信

誰が使っているかを特定する情報は集めない。

## 利用状況の記録（v1.50〜）

全体の傾向を知るために Google アナリティクス（GA4）を使う。測定IDは `data/config.json` の
`analytics.measurementId`（空にすると読み込み自体を行わない）。実装は `js/analytics.js`。

- 送るもの：画面の名前（ホーム／ガチャ／カード一覧／カード詳細／まち巡り／ミッション ほか）と、
  操作の種類と回数（ガチャを引いた・チェックインできた・外部リンクを押した・シェアした）
- 送らないもの：氏名・連絡先（入力欄が無い）、現在地の緯度経度、どのカードを持っているか、
  コインの残高、バックアップの中身、localStorage の内容
- Cookie は GA4 が使う `_ga`（同じ端末からの再訪をまとめて数えるための、ランダムな番号）だけ。
  個人を特定する値ではなく、アプリ側からは読み書きしない
- 広告向けの計測（Google シグナル・広告のカスタマイズ）は切っている（`allow_google_signals: false`）。
  送信内容に `npa=1`（広告のカスタマイズをしない）が付くことを、ヘッドレス Edge の通信記録で確認した
- 設定 →「利用状況の記録を送る」で利用者がいつでも止められる（`settings.analytics`）。
  止めると以後いっさい送らない
- 作業環境（`localhost` / `127.0.0.1` / `file://`）では読み込まない
- オフラインのときは送られない（あとからまとめて送られることもない）

改正電気通信事業法の外部送信規律には、この項目とアプリ内の「設定 → プライバシーについて」で対応する
（同じ内容を両方に書くこと）。

## 位置情報

- 自動取得はしない。`[現在地を確認]` を押したときだけ `navigator.geolocation` を呼ぶ
- 取得した緯度経度は JavaScript のメモリ変数（`geo.js` の `fix`）にのみ置く
- 判定後に保存するのは次の3つだけ
  - `spotId`（どのスポットか）
  - 初訪問済みかどうか、初訪問日時
  - 最終訪問日（日付のみ。再訪ボーナスの1日1回判定に使う）
- ガチャだけで遊ぶ利用者には、位置情報の許可を一度も求めない

## 端末内に残るもの

`localStorage` のキー `shika-gacha:state`（詳細は STATE_SCHEMA.md）。
ブラウザのデータを削除すると消える。復元手段としてバックアップファイルの保存を用意している。

Service Worker の Cache Storage に、アプリ本体・カード画像・地図タイルがキャッシュされる。
ここに個人を識別する情報は入らない。

## 外部への通信

| 宛先 | 内容 | タイミング |
|---|---|---|
| 配信元（GitHub Pages） | HTML/CSS/JS、cards.json、画像 | 起動時・表示時 |
| `tile.openstreetmap.org` | OpenStreetMap の地図タイル | まち巡り画面を開いたとき |
| `www.googletagmanager.com` / `www.google-analytics.com` | 画面の名前・操作の種類（Google アナリティクス） | 起動時と画面の切り替え・操作のたび。設定で止められる |
| `www.google.com/maps` | 検索語または緯度経度を含むURL | 利用者がリンクを押したときだけ |
| X／LINE／Facebook の投稿画面 | アプリのURLと、集めた枚数の一文 | 利用者が「SNSでシェア」から選んだときだけ |

Google Maps へのリンクには、利用者の現在地は含めない（スポットの座標または検索語のみ）。

## 実装上の確認ポイント

- `geo.js` の `fix` を localStorage へ書き出していないこと
- `visits` に緯度経度を混ぜていないこと
- バックアップファイル（`backup.js`）に座標が含まれないこと
- `analytics.js` の `trackEvent` に、カードID・座標・コイン残高を渡していないこと
- `fetch` の宛先が上表以外に増えていないこと
